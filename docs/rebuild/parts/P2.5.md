# P2.5 Auth

## Audit (live, 2026-10-08, desktop 1366 + phone 390; login, register, forgot, reset; Google + credentials enabled)

**Sign-in and accounts (server)**
1. **Email is case-sensitive.** Register stores the email as typed, and login matches it exactly. Someone who signed up as `Ahmed@Gmail.com` can't log in with `ahmed@gmail.com`, and the same person can register twice with different casing.
2. **Phone formats don't match.** Register turns `0912345678` into `+0912345678`, the checkout uses `09…`, and the placeholder suggests `+249…`. Typing `+249912345678` at login doesn't find a `+0912345678` account. A phone password reset looks up the raw input, so it never finds anyone (yet still shows "sent").
3. **Password reset doesn't sign out old sessions.** `passwordChangedAt` is saved but never checked, so a stolen session stays valid after a reset.
4. Reset tokens are stored in plain text.
5. Register and reset errors come back in English ("Password must contain…") on the Arabic page.

**Pages**
6. **Regression from P2.4:** the register phone label reads "رقم هاتف آخر", because it shares the key I renamed.
7. **Made-up claims:** the login page shows "+10K عميل نشط" and "99.9% أداء النظام", and the register page says "نظام مشفر بالكامل وآمن ٢٥٦-بت". These are made-up numbers and claims.
8. The desktop hero leads with the long shop name in 60px type, not Himmat (brand rule: Himmat leads). The copy uses the old shop name ("انضم إلى أعمال عصام الدين نصر…").
9. **Login always goes to `/`.** Pages that send you to login (`/account/*`, `/admin`, `/pos`, the checkout sign-in link) lose where you came from, so staff land on the storefront.
10. The login label says "البريد الإلكتروني" but the field also accepts a phone number.
11. Browser validation pops up in English ("Please fill out this field.") on the Arabic pages. Password rules are only shown after a failed submit.
12. "العودة للمتجر" arrows point left in RTL; back should point right.
13. "تذكرني" is a checkbox that does nothing.
14. Reset page: an expired or invalid link still shows the form, and you only learn the link is bad after typing a new password twice. The label says "كلمة المرور", not "كلمة المرور الجديدة". Forgot and reset pages have no page title.
15. Forgot password always says "تم إرسال رابط…", even when nothing can be sent. There's no fallback if the email never arrives.
16. Style: blue background blobs (off-brand), `shadow-[0_0_100px_rgba(0,0,0,0.5)]` and 40px radius cards (look AI-made). Show-password button labels are English.

## Plan (one PR, `rebuild/p2-5-auth`)

- `src/lib/auth-identity.js` (pure, tested): normalise email (trim + lowercase) and Sudan phone (`09…`, `9…`, `+249…`, `00249…`). It returns the canonical `+2499XXXXXXXX` plus the legacy `+09…`/`09…` forms, so existing accounts still match. No production data changes.
- Use it in register (store canonical forms, duplicate check on all forms), credentials login (case-insensitive email, every phone form) and reset request.
- Reset: store a SHA-256 of the token; check the link before showing the form; return error codes the page translates.
- Sessions: `refreshAuthToken` ends any session issued before `passwordChangedAt`.
- `proxy` adds `?callbackUrl=` when it sends someone to login. Login returns them there (same-site paths only); with no callback, staff go to `/admin` and customers to `/`.
- Pages: remove the made-up stats and the 256-bit line; Himmat-led short headline; real copy; Arabic validation messages (`noValidate` + our own checks); password rules shown under the field; arrow direction; drop "تذكرني"; labels; titles. Keep the current layout and colours: no blue blobs, lighter shadow, the same radius as the rest of the store.
- Forgot: neutral message ("إن كان لديك حساب بهذا البريد فسيصلك رابط") plus a store contact line as the fallback.
