# P2.6 Customer account

## Audit (local, 2026-10-09, desktop 1366 + phone 390; seed customer with 5 orders: pending, processing, shipped, cancelled, delivered)

Pages: `/account/orders`, `/account/orders/[id]`, `/orders/[id]/invoice`, `/account/notifications`, `/account/settings` (5 tabs). `/my-orders` redirects to `/account/orders` (fine).

**Wrong or made-up information**
1. **Fake tax number on every invoice.** `STORE_VAT_NUMBER` falls back to `310123456700003` (a Saudi-format sample), shown as "الرقم الضريبي" on customer invoices. The store charges no tax (P2.4).
2. **Invoice number "BACKFILL-cmusgyrfx…"**, and the invoice date is the day it was first opened, not the order date. It also lists "أمين الصندوق: النظام" (cashier: system) on an online order.
3. Preferences tab offers a newsletter sign-up (no newsletter exists) and a free-text "currency display" field that does nothing.
4. Security tab says "لا توجد جلسات مخزنة في قاعدة البيانات (طريقة الدخول الحالية قد تستخدم رمز JWT)": developer text shown to customers.

**Accounts (server)**
5. **Profile phone is saved as typed.** It skips the P2.5 phone normalisation, so `0912…` saved here can't be used to log in as `+249…` and can duplicate another account's number in a different form.
6. **Changing your own password signs you out a few minutes later with no warning**, because the P2.5 guard ends every session issued before the change, including the current one.
7. Notifications page asks for all `ORDER_STATUS` notifications without `customerOnly=1`, unlike the bell, so it can disagree with the bell.

**Orders list and detail**
8. Status and payment are raw English codes (`PENDING`, `CASH ON DELIVERY`); the status filter shows `all`, `PENDING`… Pagination says "Prev/Next".
9. Phone list shows only the order number and date: no status, total or item count.
10. Order number renders as `EIZ5HPD2#` (the `#` jumps to the end in RTL). Dates mix Arabic-Indic digits (table) and Latin (phone list).
11. Orders, order detail and notifications pages have no page title (tab shows the site name only).
12. Detail page: product names in English on the Arabic page (invoice uses Arabic), no photos or links, `x 6` quantity text, no delivery address, payment method or status shown in Arabic, "الخصم 0" always shown, no way back to the order list.
13. Detail page: "انتهت فترة الإرجاع" (return period ended) shows as a disabled button on pending/shipped orders that were never delivered. Action row uses `flex-row-reverse` in RTL (double reversal, same bug as P2.4).
14. Return window counts 14 days from `updatedAt`, which moves whenever staff edit the order.
15. Date filters show `mm/dd/yyyy` placeholders; filter button is 32px tall (small tap target).

**Settings**
16. **Regression from P2.4:** phone label reads "رقم هاتف آخر" (shared key renamed).
17. Phone shows as `249900000004+` (no `dir="ltr"`). Gender select shows "none"; language and theme selects show `ar` / `system`.
18. No account navigation: orders, notifications and settings don't link to each other (only via the header menu).

**Invoice page**
19. Back arrow points left in RTL. The header leads with the long shop name in large type, with Himmat beside it (brand rule: Himmat leads). Customer name and phone missing when the order has them on the user record only.

**Local dev only (no fix):** each logged-in page keeps a notification stream open; after ~6 page loads in one tab, the browser runs out of HTTP/1.1 connections and the next page hangs. Production uses HTTP/2. Audit script opens a fresh tab per page.

## Plan (one PR, `rebuild/p2-6-account`)

- **Invoice:** no tax number unless `STORE_VAT_NUMBER` is really set; title "فاتورة" (not "فاتورة ضريبية") when there's no tax; invoice date = order date; show the order ref instead of a `BACKFILL-` number; drop the cashier line for online orders; Himmat-led header; RTL back arrow.
- **Server:** profile phone through `phoneVariants` (canonical form; "in use" checked against every form, test-first). Own password change: sign out and send to `/login` with a "password changed, sign in again" note (safer than refreshing the token, which a stolen session could also do). Notifications page uses `customerOnly=1`.
- **Return window:** count from the delivery time (`deliveredAt` if the model has it, else the DELIVERED status-history entry), test-first. Return button only on delivered orders.
- **Orders list/detail:** Arabic status/payment labels (shared map with the bell), status-coloured badges, phone cards with status + total + items, `#` order number in an LTR span, one digit style, titles, real pagination labels, taller controls. Detail: Arabic product names with photo + link, address, payment, status, hide zero discount, back link, fixed action-row direction.
- **Settings:** fix phone label, LTR phone, Arabic option labels; remove newsletter and currency fields; hide the "active sessions" card (sessions aren't stored, so it can only ever show the JWT text).
- **Account nav:** a small tab row (طلباتي · الإشعارات · الإعدادات) on all three pages.
- Keep current layout, colours and radius.
