# P3.2 Inventory

## Audit (local seed data as admin, desktop + phone, 2026-10-14; production read was not allowed this session)

**Stock integrity (A-28, A-20)**
1. Editing a product writes the `stock` from the form. If a sale or receipt happens while the form is open, saving puts the old number back, so stock is silently wrong. No movement is recorded.
2. The +/− buttons (`updateStockQuantity`) check and then update in two steps (a race), and write no movement.
3. Stock history is missing for store checkout, cancellations, returns, refunds, manual +/− and product edits. Only POS, receive/issue and supplier purchases write `StockMovement`, so the movement log can't explain the current stock (A-28).
4. A product with orders can't be deleted (hotfix #9), but there's no clear "hide / restore" action. Users get an error and have to find the active toggle in the form (A-20 follow-up). Bulk delete skips these products without saying which ones.

**Data / speed (`src/lib/inventory.js`)**
5. The summary runs 11 queries at once, and 4 of them load every product to add up values in JS (same pool problem as A-43). A cold first load took 50 s of app time locally.
6. The month charts use `ORDER BY month ASC LIMIT 18`, which keeps the oldest 18 months, not the latest.
7. "Revenue by origin" counts cancelled orders.
8. The low and in-stock filters include hidden products, but the summary cards count only active ones, so the numbers don't match.
9. Low-stock alerts are sent again on every issue or +/− while a product stays low, which floods the notifications.
10. The cashier view hides cost prices, but the movement log still sends `unitCost`.
11. Receive/issue don't refresh the store pages that show stock.

**UI (`ProductTable`, `InventoryStockSection`, `InventoryReportActions`, charts)**
12. English on the Arabic screen: filter selects show "all", origin dropdown "IMPORTED/LOCAL", badges "IMPORTED / مستورد" (doubled), unit "pcs/roll/box", and the import-tax table shows English product names.
13. Origin is shown twice in each row (a badge under the name, plus a badge and dropdown in the origin column). The table is wider than the card on desktop, so the stock and unit columns are cut off.
14. The out-of-stock banner uses `text-red-100`, which can't be read on the light theme.
15. Charts: only "monthly receipt value" shows, and it's an empty card. The others render nothing. Recharts warns about width -1 on the server.
16. The import-tax table lists every imported product (all 0.00) in the middle of the page, which makes the page very long on phone (6,700 px).
17. The movement log fetches twice on load and shows "…" while waiting, with no loading text.
18. The cost value card wraps the currency ("ج.س") onto its own line.

## Plan (one PR, `rebuild/p3-2-inventory`)

- **One stock helper, test-first:** `src/lib/stock.js` → `changeStock(tx, { productId, delta, reason, userId, ... })` does a guarded atomic update and writes a movement (IN/OUT plus a `reason` such as SALE, CANCEL, RETURN, REFUND, ADJUST, OPENING, RECEIVE, ISSUE, POS, PURCHASE). It sends a low-stock alert only when stock crosses the minimum. Checkout, cancel, return, refund, POS, purchases, receive/issue and +/− all use it. No schema change needed: `reason` is already a string.
- **Product form:** stock is set only when a product is created (written as an OPENING movement). Edit shows stock read-only, with a link to receive/issue.
- **Hide / restore** action in the row menu and in bulk. Add a "hidden" status filter. Delete stays for products with no history, and bulk delete says how many were hidden instead.
- **Summary as SQL aggregates** (sums and counts in the DB, a few queries at a time), latest 18 months, no cancelled orders, active-only everywhere. Redact `unitCost` for cashiers.
- **UI:** translate selects, origin, units and statuses. Show origin once (a dropdown for managers, a badge otherwise). Fix the table width. Readable banner. Empty states for charts. Move the import-tax table into the report/print view. Single movement fetch. Same look, no redesign.
