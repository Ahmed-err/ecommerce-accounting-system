# P3.4 POS

## Audit (code + CI screenshots of `/pos`, desktop + phone, 2026-10-15)

**Money (A-27)**
1. The screen adds 15% tax to the total and works out the change from it, but the server saves the sale without tax. The cashier collects 15% more than the books show. The store has no tax (owner, P2.4).
2. The server takes the discount amount from the browser and only checks that it isn't more than the total. Any cashier can give up to 100% off without approval.
3. The server takes the tax amount from the browser and prints it on the receipt. `paymentMethod` isn't checked: any text is saved.
4. "آجل" (pay later) saves the sale as paid: the order is DELIVERED and the full amount is booked as income on the day. No record shows who owes the money.
5. Products with price 0 (106 in the catalogue) can be sold for 0.

**Screen (`POSClient.js`)**
6. On phone the category chips and the cart fill the screen, so no products are visible. The shop name in the header overlaps the language switch.
7. In Arabic the category and product names are English. Prices use `toLocaleString()`, so digits follow the browser. The sync time reads "AM 4:14:03".
8. The header shows the old shop name ("عصام الدين نصر") instead of the Himmat lockup that the admin uses (P3.1).
9. The shortcut bar builds labels by splitting translated strings (`searchPlaceholder.split(' ')[2]`), which shows "(F2)" in Arabic. The Pay button has a printer icon and says only "دفع".
10. Errors and "out of stock" text use dark-theme colours (`text-red-400`, `text-emerald-400`), which are hard to read in light mode. ProductCard's "OUT"/"LOW" badges are in English caps.
11. The cart saved in the browser is restored without checking the current price and stock. The server checks both, but the screen shows old totals until the sale fails.

**Dead code**
12. `components/pos/ProductRow.js` and `components/pos/ThermalReceipt.js` aren't imported anywhere.

## Plan

- **`src/lib/pos-pricing.js` (new, tested):** one function for the POS total: lines from DB prices, discount (fixed or %) checked against the role's limit, no tax, and an allowed list of payment methods. The server uses it to set the totals. The screen uses it only for display.
- **`actions/pos.js`:** ignore `taxAmount` and `discountAmount` from the browser. Accept `{ discountType, discountValue }`, recalculate, refuse over-limit discounts and zero-price lines, and check the payment method. Pay-later follows the owner's answer below.
- **`POSClient.js`:** remove the tax row. On phone, use a product grid with a scrolling chip row and a sticky cart bar that opens the cart as a sheet. Use the Himmat lockup in the header. Show Arabic names (`nameAr`) and categories, Western digits through the shared formatter, and labels from `ar.js`/`en.js` with no string splitting. Use light-safe colours. Re-check the saved cart against current products on load.
- Delete `ProductRow.js` and `ThermalReceipt.js`.
- **Tests:** `tests/unit/lib/pos-pricing.test.ts` (discount limit per role, percent rounding, zero price refused, no tax) and `createPOSOrder` (ignores browser totals).

2. "آجل" (pay later): (a) remove it for now, or (b) keep it with a required customer name and phone, saved as unpaid with no income until marked paid. That needs a "mark paid" button and a debts list, which belong to P3.5. (Recommended: (a) now, (b) in P3.5.)
