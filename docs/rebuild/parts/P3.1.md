# P3.1 Admin shell & dashboard

## Audit (local seed data as admin / manager / cashier, desktop + phone; production read-only, 2026-10-12)

Production staff: 1 active ADMIN; 1 MANAGER and 3 CASHIER accounts, all inactive.

**Data (`src/lib/dashboard.js`)**
1. ~18 queries at once, then 12 more one after another for the chart; the monthly chart loads every order of each month (A-43). Low stock loads every product to count in JS.
2. Weekly chart splits store/POS using only the 10 most recent orders, so weekly store/POS figures are wrong.
3. "Total revenue" comes from accounting transactions (106,000), "store revenue" from orders (239,000): two sources, numbers that don't add up. Average order = transaction revenue ÷ order count (mixes both).
4. Store/POS/products/low-stock cards always show "0%" change (no real comparison) with a green up-arrow.
5. Cancelled orders count as revenue.
6. Custom range parses `to` as UTC but `from` as local time.

**Dashboard UI (`DashboardClient.js`)**
7. English on the Arabic screen: range buttons "today/week/month", order status (PENDING…), source badge (STORE/POS), status list, month names on the chart.
8. Chart: Y-axis numbers overlap the axis (no thousands formatting); line hugs the edge in RTL; empty POS line drawn as a green line at 0.
9. Empty blocks shown as blank cards ("sales by category", "activity log") with no empty-state text.
10. Page title is the store's generic title (no "لوحة التحكم").

**Shell (`AdminLayoutClient.js`, `AdminSidebar.js`)**
11. "Coupons" untranslated in the sidebar.
12. Sidebar brand line truncated ("أعمال عصام الدين نصر للأ…"); the phone header shows the long shop name instead of Himmat.
13. Desktop top bar holds only the notification bell (a full-width empty strip); no page title or user/sign-out there.
14. Manager sees "المحاسبة" in the sidebar, but the proxy sends non-admins away from `/admin/accounting` (A-13). Cashier sees "لوحة التحكم" but is always redirected to orders.

**Permissions (A-12)**
15. The settings permission matrix is decorative: actions check fixed role lists, never the matrix. Production rows already disagree with what the app does (MANAGER has full "employees"/"settings" in the table but can't open them).

## Plan (one PR, `rebuild/p3-1-admin-shell`)

- **Dashboard data, test-first:** one sales source — orders, excluding cancelled — for revenue, store/POS split, order count and average; money in/out stays in the finance summary from transactions. Chart from one grouped SQL query (`date_trunc` by month or week, store vs POS). Low stock as a SQL count. Run queries in small batches. Real previous-period change for every card, or no change shown.
- **Dashboard UI:** Arabic for range buttons, statuses, sources, months (`Intl` with `ar`); formatted axis numbers; empty states; "لوحة التحكم" title. Same look, no redesign.
- **Shell:** translate "Coupons"; Himmat lockup in sidebar and phone header (shop name as a small label, per brand rule); top bar shows the page title + bell.
- **Roles:** sidebar, proxy and page checks all read one role map (`src/lib/staff-access.js`), so nav only shows what a role can open. Accounting: admin only, matching the proxy (A-13).
- **Permission matrix (owner choice below).**
