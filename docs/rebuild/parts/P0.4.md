Scope (roadmap): navbar, footer, page layouts, theme toggle, RTL/LTR, language switch, loading/error/not-found states. Admin shell is P3.1.

## Shipped (PR #16)

- Store pages in `src/app/(store)/` (same URLs) rendered by `StoreShell`: skip link, sticky 64px `SiteHeader`, one `<main id="content">`, `SiteFooter`. Root `not-found.js` uses the same shell, so unknown URLs return 404 with navigation.
- Root `loading.js` removed; static store skeleton; minimal `ErrorState` error pages; `global-error.js`; `/styleguide` metadata hidden on production.
- Header split into `SiteHeader`, `HeaderNav`, `HeaderActions`, `MobileMenu` (old `Navbar.js`, 514 lines, deleted): single named cart link announcing the count, single login link, `aria-current` on the active page, disclosure pattern for categories and account, amber logo tile in dark mode.
- Footer rebuilt: Shop / Help / Contact columns, no duplicate or placeholder links, social links only from settings (Facebook, Instagram, WhatsApp, TikTok), Sarmadax credit kept.
- Only the current language's dictionary reaches the browser (`useT()`; 60 client files via codemod); CI fails the build if dictionary text appears in client chunks.

## Final review

Whole-branch review (inline, after build). Fixed with a test:

- Important — account panel stayed open after choosing a link (header now persists across pages); it closes on any item.
- Minor — account "My orders" linked to `/my-orders` (redirect hop) → `/account/orders`; failed categories fetch was an unhandled rejection; pre-mount theme placeholder was a focusable `aria-hidden` button.

Accepted as ruled during build: unknown `/admin/*` URLs show the store 404 shell; categories open on click only; disclosure pattern instead of ARIA menus.
